# 02 · OML 体系规范 v1.0

**OML = Omni-Mantic Lattice，全域命理格。**
一套把世界各地命理体系与现代人格分类统一到十二维连续量表的计算框架，输出形如 `ROFPWM-3A` 的人格代码。

---

## 1. 设计目标与非目标

**目标**

1. **可通约**：让使用不同体系的人能谈论同一件事——八字的「日主身弱」与 MBTI 的「I」与大五的「低外向」应能在同一坐标系里被指认。
2. **可审计**：每一分从哪来必须可追溯到具体来源与权重，且能在界面上逐项展开。
3. **可归零**：象征层的影响必须是一个用户可调、可关闭的参数，而不是被硬编码进结论。
4. **可反驳**：所有系数、常模、权重都是显式数据而非隐藏常量，任何人都能替换后重算。

**非目标**

- 不预测事件、不判吉凶、不排流年。
- 不主张出生时刻会导致人格差异（象征层的定位见 §6）。
- 不用于招聘、信贷、保险、司法、医疗等高风险决策。

## 2. 十二维本体

十二维两两成轴，构成六条双极轴。**每一维独立计分**（1–99 连续量），
轴向字母只表示该轴上哪一极更突出——一个人可以同时高「曜」与高「渊」（能量丰沛型），也可以两极同低（低唤起型）。

| 轴 | 极 A | 极 B | 该轴回答的问题 |
|---|---|---|---|
| 0 能量轴 Energy Current | **R 曜** Radiance 向外辐射：表达欲、社交驱力 | **D 渊** Depth 向内沉降：独处需求、内省深度 | 能量朝哪个方向流？ |
| 1 认知轴 Cognition Mode | **L 衡** Ledger 实证：证据、结构、可验证 | **O 兆** Omen 象征：直觉、隐喻、模式跳跃 | 真相通过什么通道到达？ |
| 2 意志轴 Volition Stance | **F 锻** Forge 掌控：塑形现实、目标性 | **C 流** Current 顺势：与不确定性共处 | 面对现实是塑形还是顺流？ |
| 3 情感轴 Affective Field | **P 汐** Pulse 振幅：感受强度、共情深度 | **S 磐** Stone 稳态：抗压、复原力 | 感受是浪还是地基？ |
| 4 联结轴 Bond Geometry | **W 织** Weave 联结：亲密需求、群体归属 | **B 垣** Bastion 边界：主权、拒绝能力 | 「我们」与「我」谁在前？ |
| 5 生成轴 Becoming Vector | **M 化** Meta 变易：求新、可塑、重构 | **G 根** Ground 承续：传统、长期承诺 | 时间指向未来还是来处？ |

每个维度另附三组固定对应，供反向映射使用：**五行**（木火土金水）、**脉轮**（七轮）、**阿育吠陀体质**（vata/pitta/kapha）。
完整定义见 `src/core/dimensions.js`。

### 2.1 为什么是十二

三个约束的交集：
- **6 条轴** 才能生成 2⁶ = 64 型，与六十四卦、人类图 64 闸门同构（见 §5.2）；
- **双极展开为 12 维**，才能表达「两极同高」的内部张力——这是 MBTI 类四轴二分模型结构上无法表达的信息；
- **12** 同时是黄道十二宫、十二地支、紫微十二宫的基数，便于跨体系对位。

## 3. 出生信息算法

全部为解析式低精度实现（截断 Meeus 级数），零依赖、可在浏览器内完成。实现见 `src/core/astro.js` 与 `src/core/bazi.js`。

| 量 | 方法 | 精度 / 校验 |
|---|---|---|
| 儒略日 JD | 本地民用时按时区折算 UT；1582-10-15 起切格里历 | 与 Meeus 例 7.a 一致（测试锚点 4 个） |
| 太阳黄经 | Meeus ch.25：平黄经 + 中心差 − 章动/光行差 | ±0.01°；春分点校验 < 0.05° |
| 月亮黄经 | Meeus ch.47 主要 19 项 | ±0.3°；朔望周期校验 29.53 日 |
| 黄赤交角 ε | IAU 1980 平交角 | 2020 年 ≈ 23.436° |
| 上升点 ASC | RAMC = GMST + 经度；ASC = atan2(−cos RAMC, sin RAMC·cos ε + tan φ·sin ε) | 24 小时扫过全部 12 星座（测试）；\|φ\| > 66.4° 退化为 MC+90° |
| 年柱 | 立春（黄经 315°）换年，**不用正月初一** | 2024-02-03 癸卯 / 02-06 甲辰（测试） |
| 月柱 | 以「节」换月：月支 = ⌊(λ−315°)/30°⌋，寅月起；月干由年干**五虎遁** | 甲己之年丙作首（测试） |
| 日柱 | 干支序 = (JDN + 49) mod 60 | 1949-10-01 甲子、2000-01-01 戊午（测试） |
| 时区偏移 | 每座城市存 **IANA 时区名**，偏移按「出生的那一刻」用 `Intl` 解析 | 见 §3.1 |
| 时柱 | 真太阳时校正（经差归一到 ±180° 后，每 1° ≈ 4 分钟）；时干由日干**五鼠遁**；23:00 后按晚子时进位 | 甲日起甲子时（测试） |
| 五行权重 | 天干 1.0（日干 1.2）；地支藏干主/中/余气 0.6/0.25/0.15 再 ×1.2；月令主气再 ×1.5 | 归一化后合计为 1 |
| 日主强弱 | 同党（比劫 + 印）− 异党（食伤 + 财 + 官杀），阈值 ±0.08 / ±0.22 | 五档：身强/偏强/中和/偏弱/身弱 |
| 恒星黄道 | Lahiri 岁差 ≈ 23.85° + 1.3972°·T | 二十七宿 + 四足 |
| 卓尔金历 | GMT 相关数 584283 | 长纪元零点 = 4 Ahau（测试） |
| 闸门轮 | Gate 41 起于黄经 302°，每闸 5.625°，六爻等分 | 标注为 `approximate: true` |

### 3.1 出生地与时区解析

使用者只选出生城市，不填 UTC 偏移。城市库来自 GeoNames（CC BY 4.0）：
主库 34,125 座（人口 ≥15000，244 个国家与地区），补充库 35,542 座（5000–15000）按需加载。

关键设计是**存时区名而非固定偏移**：每座城市记 IANA 时区名（如 `Asia/Shanghai`），
偏移由运行环境自带的 IANA 时区库按出生时刻解析。于是以下情形自动正确：

| 情形 | 例 |
|---|---|
| 夏令时 | 纽约 1990-07 为 −4，1990-01 为 −5 |
| 历史时区变更 | 中国 1986–1991 年实行夏令时，1988-07 的北京是 **+9** 而非 +8 |
| 非整点时区 | 印度 +5:30、尼泊尔 +5:45、纽芬兰 −3:30 |
| 标准时之前 | 1890 年的上海为 +8:05:43（地方平太阳时） |
| 切换点出生 | 前拨空档中的时刻标记 `nonexistent`，回拨重复的时刻标记 `ambiguous` |

墙上时间 → 瞬间不是一一映射，故用切换前后的偏移各推一个候选瞬间再回代验证：
两个候选都成立且不同即为 `ambiguous`（取较早一次），都不成立即为 `nonexistent`（取切换后偏移）。

**中国统一按北京时间。** GeoNames 依 IANA 给新疆标 `Asia/Urumqi`(UTC+6)，那是民间习惯用时；
而出生证明、户籍与医院记录全国一律使用北京时间，使用者报出的时刻属于后者，按 +6 计算会整体错两小时。
需要新疆时间者可在界面「高级」中手动覆盖。

**经差必须归一到 ±180°。** 汤加位于西经 175° 却使用 UTC+13（中央经线 195°），
直接相减得 −370°，换算成真太阳时便是 −24.7 小时的荒谬值。该归一同时作用于 `bazi.js` 的时柱计算。

真太阳时校正量可以很大且完全真实：喀什 1988-07-01 08:00 → UTC+09:00 且校正 −236 分钟，
真太阳时为 04:04，时柱因此前移一个多时辰。理论上限为 ±180 分钟（单一时区最宽跨 ±45° 经度）。

**未处理的已知问题**：城市库覆盖到人口 5000 以上（更小的聚落需选邻近城市，经度每差 1°
只影响真太阳时约 4 分钟）、极区上升点、出生时间不确定性（±2 小时可能改变时柱与上升星座）。

## 4. 问卷与计分

### 4.1 OML-144 标准问卷

- **144 题** = 12 维 × 12 题，每维 **8 正向 + 4 反向**。
- 7 点李克特量表（1 完全不符合 … 4 中性 … 7 完全符合）。
- 题序固定伪随机打散，且做局部推离以避免同维度连续出现（测试断言相邻同维 ≤ 6 处）。
- 另有 10 道情境题，不计入十二维（见 §7 与 docs/05）。

反向题的作用是抵消默认同意倾向：全部选 7 时，各维原始分为 (8−4)/12 = **0.333** 而非 1.0，
并触发「默认同意偏差」与「低一致性」两条效度警示。

### 4.2 计分公式

```
x_i     = k_i · (r_i − 4) / 3                       单题归一化，k = ±1，x ∈ [−1, 1]
Q_d     = mean_{i∈d} x_i                            维度原始分 ∈ [−1, 1]
Zq_d    = (Q_d − μ_d) / σ_d                         按常模标准化
B_d     = 2.4 · Σ_s w_s·vec_s[d] / Σ_s w_s          象征先验（见 §5）
Z_d     = (λq·Zq_d + λb·B_d) / √(λq² + λb²)         保持单位方差的复合
Score_d = clamp(round(50 + 15·Z_d), 1, 99)
```

- λq ≡ 1；λb ∈ [0, 0.40]，默认 **0.15**，由用户在界面上直接控制。
- 分母 √(λq² + λb²) 假设问卷分与象征先验不相关（ρ = 0）。这是一个**已知的简化**：
  若未来实证发现二者存在相关，应改用 √(λq² + λb² + 2λqλb·ρ)。
- 结果附 95% 区间，宽度由该维已作答题数决定。

### 4.3 效度指标

| 指标 | 定义 | 触发警示 |
|---|---|---|
| 完整度 completeness | 已答题数 / 144 | < 0.90 |
| 离散度 variability | 全部作答的标准差 | < 0.60（直线作答嫌疑） |
| 默认同意偏差 acquiescence | 全部作答均值 − 4 | \|·\| > 1.20 |
| 正反一致性 consistency | 1 − mean(\|正向题均值 − 反向题均值\|)/1.2 | < 0.55 |

总体置信度 = 0.45·完整度 + 0.35·一致性 + 0.20·min(离散度/1.4, 1)。

### 4.4 常模（当前的最大局限）

`NORMS` 中的 μ / σ 目前是**设计常模**：以量表中点加轻度默认同意偏差为基准的先验值，
不是实证分层常模。这意味着：

> **分数的相对结构（哪一维更高、代码取哪个字母）是可靠的；分数的绝对位置（「62 分」意味着超过多少人）目前没有实证含义。**

替换路径：收集 ≥1000 份完整作答，按语言/地区/年龄分层计算各维均值与标准差，
替换 `src/core/scoring.js` 的 `NORMS` 即可，无需改动其他代码。

## 5. OML 代码

### 5.1 结构

```
R O F P W M - 3 A
└─────┬────┘   │ │
   六条轴的显性极  │ └── 调性：A 协 Attuned / T 荡 Turbulent
                └──── 五行主导：1木 2火 3土 4金 5水
```

代码空间：**64 核心型 × 5 五行 × 2 调性 = 640 种**。

### 5.2 核心型 ≡ 六十四卦

轴 0 为初爻、轴 5 为上爻；每轴取极 A 记阳（1），极 B 记阴（0），自下而上组成六爻，
再经文王卦序表得卦号。例：`ROFPWM` → 爻 `[1,0,1,1,1,1]` → 下卦离、上卦巽 → **风火家人**。

这不是修辞。二元占卜（六十四卦、约鲁巴 256 奥杜、阿拉伯沙占十六图）与二分类型学（MBTI 16 型）
在组合学上是同一件事：用 n 个二元轴枚举 2ⁿ 个状态。OML 只是把这条同构显式写了出来，
因此 **OML 核心型可与人类图/基因钥匙的 64 闸门直接互译**。

同时输出两个变换卦：**综卦**（六爻倒转，「同一件事的另一端」）与 **错卦**（阴阳全反，「完全相反的操作系统」）。
它们在关系相性中作为加成项使用（见 docs/04）。

### 5.3 调性后缀 A/T

```
张力 tension  = mean over axes of max(0, min(z_极A, z_极B))
coherence     = 0.40·z_磐 − 0.35·z_汐 + 0.15·z_垣 + 0.10·z_根 − 0.55·张力 + 0.15·(一致性 − 0.7)·2
temper        = coherence ≥ 0 ? 'A' : 'T'
```

「张力」度量**两极同时偏高**造成的内部拉扯——比如既极度渴望联结（织）又极度需要边界（垣）。
这是双极模型独有的信息量。

**与 16Personalities 的 -A/-T 的区别**：后者基本等价于神经质的反向。
OML 的 A/T 额外计入轴向张力与作答一致性，因此**一个情绪敏感（高汐）但内部自洽的人仍可能是 A**。

### 5.4 型名

型名由前缀（轴 0–2，8 种）× 后缀（轴 3–5，8 种）组合而成，共 64 个：

| 前缀 | | 后缀 | |
|---|---|---|---|
| RLF 明锻 Forgelight | RLC 朗流 Clearstream | PWM 潮织者 Tideweaver | PWG 潮守者 Tidekeeper |
| ROF 曜启 Sunherald | ROC 焰漂 Emberdrift | PBM 潮行者 Tidewalker | PBG 潮岸者 Tideshore |
| DLF 深锻 Deepforge | DLC 静衡 Stillscale | SWM 磐织者 Stoneweaver | SWG 磐守者 Stonekeeper |
| DOF 玄锻 Veilforge | DOC 幽流 Mistflow | SBM 磐行者 Stonewalker | SBG 磐岸者 Stoneshore |

例：`ROFPWM` = 曜启·潮织者 / Sunherald Tideweaver。

### 5.5 五行代号

```
fromDims[e]  = Σ_{d: dim.element == e} z_d，再按最大绝对值归一
fromBazi[e]  = (八字五行占比_e − 0.20) × 5
blend[e]     = (1 − w)·fromDims[e] + w·fromBazi[e]，  w = 0.35 + λb
element      = argmax_e blend[e]
```

λb 越高，八字五行结构的话语权越大；λb = 0 时仍保留 0.35 的八字权重——
这是一个**刻意的设计选择**：五行代号被定位为文化符号标签而非特质断言，因此不随 λb 完全归零。
若需要纯问卷的五行标签，取 `dominantElement(dims, null)`。

## 6. 象征层的认识论定位

OML **不主张**出生时刻会导致人格差异。象征层的定位是：

> **文化语义的翻译通道。** 它让「我是天蝎座」「我日主身弱」「我是 5 号」这些自我描述
> 能够被放进同一个坐标系里互相对话，而不是宣称它们能预测行为。

由此产生三条硬性设计约束：

1. **默认权重低**：λb = 0.15，象征层约占最终分数 15% 的方差贡献。
2. **必须可归零**：λb = 0 时，出生信息对分数的影响**严格为零**（有测试断言：换一个完全不同的生日，
   λb = 0 时十二维分数逐位相等）。
3. **必须逐项可见**：结果页展开每个符号来源的权重、取值与它推动了哪些维度。

映射系数（`src/core/mapping.js`）是**设计参数**——由体系语义的结构化对齐得到，不是实证回归系数。
它们的作用是保持翻译的一致性，不是宣称因果。

## 7. 情境题与身份字段

10 道情境题分四类 scope：

| scope | 字段 | 用途 | 是否进入特质计算 |
|---|---|---|---|
| `identity` | 性别认同、人称、性/浪漫倾向 | 称谓 | **否，永不** |
| `matching` | 希望被匹配的性别、关系形态、亲密节奏 | 关系相性的准入层 | **否**（只影响相性分，不影响本人维度分） |
| `prior` | 自陈 MBTI / 九型 / 血型 | 象征先验的可选来源 | 是（经 λb 缩放） |
| `config` | λb 象征层权重 | 计算配置 | — |

测试断言：遍历 9 种性别认同与 8 种性倾向标签，其余输入不变时，
**十二维分数与 OML 代码完全一致**（`tests/matching.test.js`）。详见 [05-ethics-inclusion.md](05-ethics-inclusion.md)。

## 8. 版本与替换接口

| 想替换什么 | 改哪里 | 是否需要改其他代码 |
|---|---|---|
| 常模 μ / σ | `src/core/scoring.js` → `NORMS` | 否 |
| 某体系的映射向量 | `src/core/mapping.js` → 对应 `*_VECTORS` | 否 |
| 各来源权重 | `src/core/mapping.js` → `SOURCE_WEIGHTS` | 否 |
| 题目文本 / 增删题 | `src/core/questionnaire.js` → `ITEMS` | 否（测试会校验每维题数与正反配比） |
| 城市库 / 中文城市名 | `scripts/build-cities.js` 后重跑该脚本 | 否（测试会校验时区合法性与显示名） |
| 匹配函数与权重 | `src/core/matching.js` → `DIM_MATCH_CONFIG` | 否 |
| 影响力排名子分 | `src/data/systems.js` | 运行 `node scripts/gen-ranking.js` 重生成文档表 |

版本号写在每份档案的 `version: 'OML-1.0'` 字段中。任何会改变既有代码结果的修改都应递增次版本号。
