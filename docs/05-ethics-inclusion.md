# 05 · 伦理与包容性设计

这份文档描述 OML 里那些**用代码而不是用声明**来兑现的约束。
每一条都对应 `tests/` 里的至少一个断言——如果哪天有人改坏了，测试会失败。

---

## 1. 核心原则：身份 ≠ 人格

> **性别认同、性倾向、关系形态、人称代词在任何计算路径上都不作为人格特质的预测变量。**

它们只用于两件事：

1. **称谓**——用你希望的方式称呼你；
2. **关系匹配的双向意愿**——你希望被谁匹配，这只能由你自己声明。

### 为什么这条必须是硬约束

命理学史上最有害的部分，恰恰是「由不可选择的属性推断人的品质」：
从面相术到骨相学到「女命伤官克夫」，形式各异，结构相同。
一个声称统一了所有命理体系的框架，如果不在这一点上划线，就会把这些结构一起继承下来。

而在性别与性倾向上，这个风险格外具体：传统合婚体系里存在大量以性别定吉凶的条目，
默认异性恋单偶制是唯一形态；把它们原样编码，等于把上世纪的婚配规范写进算法。

### 代码层面的兑现

| 约束 | 实现 | 测试 |
|---|---|---|
| 身份字段不进入特质计算 | `sanitizeContext()` 只保留匹配所需字段；`symbolicPrior()` 从不读取 gender/orientation | 遍历 9 种性别认同，十二维分数与 OML 代码**逐位相等** |
| 性倾向标签不改变相性分 | 准入层只读 `attractedTo`，不读 `orientation` | 遍历 8 种性倾向标签，相性总分**完全相同** |
| 同性/异性/非二元配对同分 | 准入层是集合运算，与性别组合无关 | 相同人格下，异性恋、女同、男同、非二元四种配对**总分与配对代码完全一致** |
| 合婚规则对称 | 日主生克不区分方向；无「男命/女命」分支 | `baziAffinity(A,B) === baziAffinity(B,A)`，且交换性别标签结果不变 |

## 2. 包容性的具体设计

### 2.1 性别

- 11 个选项：女性、男性、非二元、性别流动、无性别、跨性别女性、跨性别男性、间性、探索中、不愿透露、自我描述。
- 人称代词为**自由文本**，不从性别推导。
- **全部字段可留空**，留空不影响测评结果的任何部分。
- 匹配时的性别归并（woman / man / nonbinary / unknown）**只用于意愿集合运算**，
  不用于定义身份，也不出现在结果描述里。

### 2.2 性与浪漫倾向

- 采用**自陈标签**而非量表推断：异性恋、同性恋、双性恋、泛性恋、无性恋谱系、无浪漫倾向谱系、酷儿、探索中、不愿透露。
- 「性倾向标签」与「希望被匹配的性别」是**两个独立字段**——这允许标签与实际匹配意愿不一致的情况
  （如探索中、或标签与当下意愿不同步）。
- 无性恋/无浪漫谱系用户可选择「暂不寻求」，此时算法不输出恋爱相性分，但仍可用**伙伴模式**查看合作相性。

### 2.3 关系形态

- 五种形态并列，**没有一种是默认或标准**：单偶、开放式、多元关系、柏拉图优先/酷儿式伙伴（QPR）、尚未确定。
- 形态差异输出为**协商提示**而不是扣分判决：「单偶 ↔ 多元」给出 0.45 的相容系数并提示需要早期明确边界，
  而不是宣布不可行。

### 2.4 语言

- 全部结果文案避免性别化措辞与「另一半」「男女双方」这类预设。
- 依恋、爱之语、建议与风险的文案对任何性别组合同样适用。

## 3. 不做什么

| 不做 | 原因 |
|---|---|
| **不做外貌推断** | 面相、手相虽列入普查表，但明确不纳入计算。基于外貌特征推断人格的技术在历史上直接服务过种族与阶级歧视，现代「AI 面相」的复现使风险不减反增。 |
| **不做高风险决策** | 不得用于招聘筛选、绩效、信贷、保险、司法或医疗决策。人格量表在选拔场景的效度与公平性在学界长期存疑，象征层更无此类效度。 |
| **不做健康与心理诊断** | 中医体质、阿育吠陀、脉轮的反向映射是**语义翻译**，不是体检结论，不构成任何医疗建议。 |
| **不做命运预测** | 不排流年、不判吉凶、不给「什么时候能结婚」这类回答。 |
| **不做文化挪用式映射** | 北美原住民药轮/图腾体系只列入普查、不做映射：其商业化改写争议严重，且各部族传统差异极大，不存在可被安全统一的单一体系。伊法 256 奥杜同理——只指出它与 64 卦的组合学同源，不映射其诗文语义。 |

## 4. 数据与隐私

- **全部计算在浏览器本地完成。** 没有后端、没有账号、没有遥测、没有第三方脚本与字体请求。
- 出生信息与答卷只写入 `localStorage`（键名 `oml.profiles.v1` / `oml.draft.v1`），
  可在页面上逐条删除，或清除浏览器数据一次清空。
- 导出的 JSON 档案由用户自己保管——它包含完整的出生信息，**分享前请注意这一点**。
- 部署为纯静态站点，服务端不接收任何作答数据。

## 5. 象征层的认识论诚实

OML 不主张出生时刻会导致人格差异。象征层的定位是**文化语义的翻译通道**，因此：

1. **默认权重低**：λb = 0.15，约占最终分数 15% 的方差贡献。
2. **可完全归零**：λb = 0 时出生信息对分数的影响严格为零（有测试断言）。
3. **逐项可见**：结果页展开每个符号来源的权重、取值与它推动了哪些维度，用户可以自己判断要不要信。
4. **权重差异反映证据强度**：血型的权重上限被刻意设为最低（0.10），因为它的实证支持最弱；
   自陈心理量表（MBTI 0.90、九型 0.70）权重较高，因为它至少是本人对自己的直接陈述。

我们也承认相反的风险：**给伪科学一个精确的数字，可能让它显得比原来更可信**。
对此的对策是把不确定性同样精确地显示出来——95% 区间、四项效度指标、
象征占比、轴向清晰度、以及每一处「近似」的显式标注。

## 6. 已知的伦理风险（未解决）

1. **巴纳姆效应**：任何人格描述都容易让人觉得准。OML 的分维描述同样受此影响，
   分数区间与效度指标只能部分缓解。
2. **自我实现**：拿到「垣 30」的人可能因此更少拒绝别人。类型标签会反过来塑造行为，这无法通过算法消除。
3. **精确性的错觉**：640 种代码与两位小数的系数会制造一种科学感，而常模目前尚未实证（见 docs/02 §4.4）。
4. **匹配分被当作门槛**：算法定位是沟通起点，但没有任何技术手段能阻止它被当成筛选工具。
5. **文化偏置**：「趋同/互补」的分配来自当代都市亲密关系假设；十二维的语义划分本身也带有特定文化视角。

这些风险写在这里，是因为它们目前**没有被解决**，只是被公开了。
